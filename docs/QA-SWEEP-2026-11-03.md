# Browser sweep of 0b9a055 (2026-11-03)

Six agents used the app in real Chromium, each with its own account and context: five on a
local instance with a throwaway database, one read-only on production (no sign-in, bot user
agent, every non-GET blocked). Nothing was fixed. Each finding below needs a test that fails
first, at the layer where the bug lives.

"Re-run" means Claude reproduced it again after the agents finished. The others were seen only
by the agent that reported them, so treat them as claims to check.

Status: findings 1 to 4 under "Fix first" are fixed, and the same scripts confirm it in a real browser.
A tab that loaded the previous bundle still sends its stale `published` on "Save mine anyway" until it
is reloaded. Findings 5 to 7 and everything below them are open.

## Fix first

### 1. "Save mine anyway" writes a stale `published` (high, re-run)
`useSiteConflict.overwrite` passes `publicationRef.current`, which is undefined unless the refused
save was an explicit publish choice. `performSave` then falls back to `publishedRef.current`
(`EditorPage.jsx:1721`), the value the tab loaded. The forced save has no `base_revision`.

- Tabs A and B on an unpublished site. B publishes. A edits, saves, gets the 409 and presses "Save
  mine anyway". Result: `published=false`, every `PublishedPage` row deleted, `/s/` 404, no warning.
- Tabs A and B on a published site. A unpublishes. B edits and overwrites. Result: `published=true`
  with no rows: the public API serves the old live schema while `/s/` answers 404.

### 2. Ctrl+Z after unpublishing brings the site back, hidden page included (high, re-run)
`restore_snapshot` (`live_pages.py:289-291`) restores `private_pages` and `published` from a snapshot
taken before the unpublish, and the editor keeps `livePast` through an unpublish.

Send Home and About live, hide About, unpublish, Ctrl+Z. Result: `published=true`,
`private_pages=[]`, `/s/<slug>/` 404, `/s/<slug>/about/` 200. The page the owner hid is the only page
visitors can reach.

### 3. After an unpublish, sending one page exposes the others (high, re-run)
`SiteSerializer.update` deletes the rows on unpublish (`serializers.py:766`) but leaves `live_schema`,
and `send_page_live` merges into it.

Publish Home, About and Team. Unpublish. Send only Home. Result: anonymous
`GET /api/public/sites/<slug>/` returns all three pages, and a clone by another account copies them,
while `/s/<slug>/about/` is 404. Content the owner took offline is readable again. Related, API only:
hide a page while unpublished, then `PATCH published=true` without pages; the hidden page is served.

### 4. An undo from another tab clears hide flags (medium, re-run)
`restore_snapshot` overwrites `private_pages` wholesale, also for a page-scoped snapshot, and
`live-undo` sends no `base_revision`.

Tab 1 sends Team live. Tab 2 hides About. Tab 1 presses Ctrl+Z. Result: Team goes off live and
`private_pages` becomes `[]`. The next "Send draft live" publishes About. Undoing an older whole-site
send also restores rows of pages hidden since. The handoff says a page-scoped restore cannot disturb
another page: it does disturb this list.

### 5. Ctrl+Z can change the public site when the user means to undo a draft step (medium, re-run)
`livePast` survives `loadIntoDraft` and history restores, which clear the draft's own steps.

Send About live, save an edit, History → Load an old version, Ctrl+Z. Result: `/s/<slug>/about/` goes
from 200 to 404 and only a small header note says so. Same after "Copy live to draft", and in a long
Ctrl+Z run once the draft's own steps are used up. Decide whether a live step should need more
than a stray Ctrl+Z.

### 6. A block added to a full or too-deep parent is lost after "Saved" (medium, re-run)
`addComponent` and `duplicateComponent` in `editorStore.js` skip the `MAX_NESTING_DEPTH` and
`MAX_CHILDREN` checks that `moveComponentInto` has. `sanitize_component` then drops the block on the
server, the save answers 200 and the block is gone after a reload. Seen by placing from the palette
into a depth-4 container, and by Ctrl+D or placing into a parent with 60 children.

### 7. The editor header overflows on a published site from 768 to 1099px (medium, re-run)
Header width 922 at 800px and 1082 at 1024px (English), so the page scrolls sideways and "Published"
and "More actions" start off screen. Unpublished sites fit. 90304cb fixed only 1280px and up.

## Medium

- **Browser Back with Auto-save off drops unsaved work with no prompt (re-run).** `useEditorAutoSave.js`
  notes the gap. Reload and close are guarded; Auto-save on saves while unmounting.
- **History is hard to use from the keyboard (re-run).** 61 Tab presses from the opener to the panel, Esc
  only works with focus inside, and closing sends focus to the first element of the page. It does not
  use `useEscapeToClose` or `useInitialDialogFocus`.
- **Per-file "Go live" and hide exist only in the right-click menu.** The Menu key works. A synthetic
  long press did not open it, and iPadOS Safari probably fires no `contextmenu`. Not tried on a real
  device. A "..." button on the row would solve both.

## Low

Re-run:

- The Live view is a blank "refused to connect" frame when home is not live: the 404 for `/s/<slug>/`
  carries `X-Frame-Options: DENY`.
- `page-live`, `page-visibility` and `live-undo` answer 500 to a non-object JSON body (owner token needed).

Agent only:

- A file shows red while still served after delete, save and Ctrl+Z.
- `hidden` is read with `is True`, so `{"hidden": "true"}` un-hides a page.
- A hidden page moved to first place makes `/s/<slug>/` 404 (API; UI path not checked).
- Whole-site rows without a usable `pageId` can serve a hidden page when the counts disagree (API, owner's
  own content).
- Page names over 80 characters are cut by the server after the address was built from the long name.
- The file list and address disagree for non-Latin and duplicate names ("你好" is `page.html` at `/page-6/`).
- A 6 MB source save says "Please try again", which can never work (`RequestDataTooBig` has no `code`).
- Two tabs losing their session at once: the second recovery draft replaces the first.
- A site deleted in another tab: the editor only says "The requested item was not found."
- Draft/Live is `role=radio` without arrow keys. The file menu stays open on Tab and has no Home/End.
- Live state is colour only for sighted users (screen readers get text).
- Turkish copy: "Public'te gösterme" where the app says "herkese açık"; "Canlıya al", "Canlıya aktar" and
  "Canlıya gönder" name one action.
- `/site/<slug>` toolbar clipped at 768px (one run). File-row tap targets are 20px.

## Production (read-only)

No clear fault: no page errors, no 5xx, no overflow at 375 or 1280px, `/s/` sandbox intact, and the
public API shows no private field. Only one site is published, so per-file live could not be observed
there. Suggestions; those marked Caddy need the owner's OK:

- `sitebuilder-logo.png` is 491,794 bytes with no `Cache-Control` and loads twice per page (re-run for
  size and header): about 1 MB of a 1.27 MB login page.
- Hashed `/assets/*` and `index.html` have no `Cache-Control` (Caddy).
- A missing `/assets/*` file answers 200 with HTML (re-run; Caddy).
- The app document has no CSP (Caddy; the one on `/api/` would break Google Fonts as it stands).
- The static shell has `lang="en"` and no description or social tags. Unknown paths are soft 404s.

## Checked and fine

- No outsider could read an unsent, hidden or old-version page outside the flows above, or change any
  row: anonymous, another account and share-viewer got 401 or 404 on every owner endpoint, and the rows
  read back unchanged. Published pages cannot reach the app's token through any frame.
- File colours matched what `/s/` served in 20+ scripts, apart from the findings above.
- Other 409 choices, History recovery of the loser, the +1 revision rule, failing, slow and offline saves,
  session recovery, the guest limit and sign-in.
- All 23 block types, published layout at 1000, 390 and 1440px, undo chains, HTML source edge cases, SEO
  escaping, project export and import, templates, Esc and focus return in dialogs, contrast in both themes.

## Not tested

- Palette drag into parents, form submission, image uploads, code projects, the theme editor.
- Real phones and tablets, screen readers, Firefox. Anything signed in on production.
- Concurrent saves: six parallel PUTs gave one 200 and five 500s on SQLite, probably "database is locked",
  but the traces were not read and SQLite does not honour `select_for_update`. Worth a run on Postgres.
- Production caching of a hidden page (`/s/` is `public, max-age=60`) and custom domains.
